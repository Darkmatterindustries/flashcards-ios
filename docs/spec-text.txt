Front side - full-screen flashcard
On iPhone 16 Pro Max, the flashcard fills almost the entire screen. No action buttons are shown. The count sits quietly
near the bottom as an overlay.

The full-screen card is the experience. Everything
unrelated to learning is visually removed.

progress count should remain.

Swipe behavior and looping logic
Left and right swipes are not just navigation. They control whether a card remains inside the active study loop.
Swipe left = keep in loop
Looping
When the user swipes left, the current card leaves
to the left and goes to the back of the queue.

Continuous left swipes create an endless loop: A →
B → C → A → B → C ...
Swipe right = remove from loop
Session removal
When the user swipes right, the current card is
removed from the active loop and should not
appear again during the current cycle.
Example sequence:
Start with active deck: A, B, C
Swipe left on A → queue becomes B, C, A
Swipe left on B → queue becomes C, A, B
Swipe right on C → C is removed, active queue
becomes A, B

0 6 / P R O D U C T R U L E S
Design rules, behavior rules, and acceptance criteria
This final specification summarizes the updated product behavior requested for the prototype PDF.
Visual rules
Phone target: iPhone 16 Pro Max.
Flashcard surface takes almost the full screen.
Only a tiny count such as 12 / 40 appears near the
lower bottom as an overlay.
No extra on-screen buttons or distracting controls
in study mode.
Interaction rules
Tap card = flip front/back.
Swipe left = keep card in active loop and send it
to the back.
Swipe right = remove card from the active
repeating loop.
If only A and B remain, repeated left swipes cycle 
A → B → A → B.
Motion rules
Flip animation should feel like one physical card
turning over.
Left swipe should visually fade/slide the card out
to the left.
Right swipe should clearly communicate dismissal/
removal from the loop.
Animations should stay quick and lightweight for
repeated study.
Acceptance criteria
Deck tap opens study mode immediately.
User can study without visible action buttons.
Front and back are reachable only by tapping the
card.
Loop/removal logic matches the A/B/C examples
described above.
Product intent
The experience should feel almost frictionless: open deck, focus on one card, tap to reveal, and use simple directional swipes
to control repetition. The UI should disappear as much as possible so the study behavior becomes natural and fast.
